02

Data Architecture

All vehicle data lives in a single source of truth: lib/ev-data.json. TypeScript interfaces in lib/data.ts export a typed DATA singleton consumed by every component.

{
details: DetailRow[] // ~140 trims across 17 vehicles, ~35 fields each
preowned: PreownedRow[] // pre-owned pricing, synced with details
count_data: CountRow[] // sales & availability by model year (2021-2027)
count_totals: CountTotals // annual sums
us_ev_sales: USEVSales // market context (630K-1.3M vehicles/year)
glossary: GlossaryRow[] // field definitions
assumptions: AssumptionRow[] // PA tax 6%, fees $905
}

Out-the-Door Price Formula

New vehicle:
otd_new = (msrp + destination) × 1.06 + $905

Pre-owned vehicle:
otd_preowned = price × 1.06 + $905

Fee breakdown:
$905 = $422 doc + $233 title/reg + $250 EV road-use fee

04

Automated Data Pipeline

The pipeline is driven by Claude Code slash commands (skills). Each skill defines structured phases with validation gates, user approval checkpoints, and automatic OTD recalculation.

Web Research
Claude Code searches OEM sites, EPA databases, and automotive reference sites using WebSearch and WebFetch. Findings are compiled into structured comparison tables.
User Approval Gate
All proposed changes are presented as delta tables. Deltas exceeding thresholds (e.g., pre-owned price changes >$2,000) are flagged for explicit review. No data is written without approval.
Data Mutation
Approved changes are written to lib/ev-data.json. Both details and preowned arrays are updated in sync. Protected fields (seats, cargo dimensions) are never auto-modified.
OTD Recalculation
The recalculateAllOtd() utility recomputes out-the-door prices for every entry based on current MSRP, destination, and pre-owned ranges using the standard formula.
Validation
The data validator checks: required fields, OTD consistency (<$50 tolerance), numeric sanity ranges, count totals reconciliation, details↔preowned sync, and TypeScript build. Errors block deployment.
Git Commit
Changes are committed with a descriptive changelog. Vercel auto-deploys from the repository on push.
Google Sheets Sync
The full details array is pushed to a Google Sheet via service account authentication — a shareable backup with ~140 rows and ~35 columns.
05

Skill Commands

Each slash command is a structured Claude Code skill with defined phases, guardrails, and output expectations.

Command Purpose Key Behavior
/refresh Full 5-phase data refresh Pre-owned pricing → TBD resolution → spec corrections → new vehicle detection → gap filling. Cross-checks all critical fields against OEM & EPA sources.
/add-vehicle Add a new 3-row EV Researches all trims, populates all fields, updates 4 files (data, types, CSS, glossary), calculates OTD, validates, and commits.
/update-pricing MSRP & pre-owned updates Searches KBB, TrueCar, Cars.com. Flags deltas >$2K. Requires user approval. Updates both details and preowned arrays.
/scan-watchlist Monitor unreleased vehicles 3-phase: update existing watchlist → scan for new 3-row EVs → check graduation criteria for adding to main dataset.
/spot-check Quick manual audit User-directed verification of specific vehicles or fields against live sources.
/validate Read-only integrity check Required fields, OTD consistency, numeric ranges, count totals, array sync, TypeScript build. Errors block deployment.
/add-field Extend the data model Adds a new spec field to DetailRow across all entries, updates interfaces and UI registry.
/sync-sheet Push to Google Sheets One-way sync of details array to Google Sheets backup. Graceful no-op if credentials are missing.
06

Guardrails & Constraints

  • Never hardcode counts. Vehicle and trim counts are always derived from DATA at runtime — no hardcoded “140 trims” or “17 vehicles” anywhere.
  • Protected fields. Seats, cargo dimensions (behind 3rd/2nd/1st row), fold-flat, and cargo floor width are never auto-modified — they are intentionally set per seat configuration.
  • Array sync. The details and preowned arrays must stay in sync: same vehicle names, matching preowned_range values.
  • OTD consistency. Out-the-door prices are always recalculated via the standard formula. Validator flags errors at >$50 deviation and warnings at >$1.
  • Count totals. Year-column sums in count_data are reconciled against count_totals after every vehicle add or remove.
  • TBD vs. null vs. N/A. null = field doesn’t apply (no frunk). "TBD" = not yet found. "N/A" = not applicable for this trim.
  • User approval gate. No data is written to the source of truth without explicit user review and approval of proposed changes.
