## P0

1. **The retention formula does not establish original MSRP.** The plan accepts any numeric MSRP whose status is other than `unknown`. That includes current and announced prices. Even a sourced historical price needs to match the original MSRP for the exact model year and configuration to support the proposed claim. Require evidence for that denominator, disclose how many eligible rows lack it, and describe the numerator as an estimated used-market price. [Retention calculation](/Users/dan/Coding-Projects/ev-suv-comparison/docs/plans/insights-stories-v2.md:68)

2. **The backfill fallback conflicts with `data-contract`.** Step 0 allows approved reference sites generally, but the field-level policy restricts MSRP and destination to OEM domains, with a Car and Driver exception for Tesla. Kia and Rivian backfills from other reference sites would fail the check. Make the backfill opportunistic, leave unsupported values null, and require evidence that separates destination from base MSRP where the source quotes a combined price. [Step 0](/Users/dan/Coding-Projects/ev-suv-comparison/docs/plans/insights-stories-v2.md:91) · [Source policy](/Users/dan/Coding-Projects/ev-suv-comparison/scripts/refresh/source-policy.json:32)

3. **The choice headline presents historical model-year coverage as current inventory.** Of the 45 rows for model year 2026, 25 are `used_only`. The proposed “Now there are 41” implies those deduplicated trims are available new today. Reading all of `DATA.details` also leaves the existing watch-list and future-year exclusions unspecified. Preserve those rules, define which availability states count toward historical offerings, and name the latest charted model year in the headline. Generate the headline and dek from the same aggregation so the dek cannot retain the old `count_data` population. [Choice story](/Users/dan/Coding-Projects/ev-suv-comparison/docs/plans/insights-stories-v2.md:42) · [Current aggregation](/Users/dan/Coding-Projects/ev-suv-comparison/lib/data-stories.ts:58)

4. **A missing new dot does not establish that a model is no longer sold new.** `bestValueTrims()` also drops rows without a numeric MSRP, a positive range, or a qualifying configuration. Determine whether the model is sold new from `availability` across its rows, then separately report whether a qualifying new price-per-mile figure exists. Label both endpoints as the best eligible values so “New, it’s $226” does not imply the same trim was priced twice. [Used-market chart](/Users/dan/Coding-Projects/ev-suv-comparison/docs/plans/insights-stories-v2.md:56) · [Current value selector](/Users/dan/Coding-Projects/ev-suv-comparison/lib/data-stories.ts:128)

5. **The third-row chart turns a legroom cutoff into an unsupported fit claim.** The plan labels 28 inches “adult-size” without evidence that this measurement alone establishes adult fit. It also admits rows with unknown legroom into the cohort it calls adult-size and directs tests to classify `N/A` as “not published,” even though that can mean the configuration has no third row. Use “28-inch legroom cutoff,” distinguish those cases, and specify a deterministic trim selection rule. Scope the superlatives to the plotted trims with published measurements. The current ID. Buzz lead over the Lucid Gravity is 8.9 inches, so the illustrative “by ten inches” also needs correction. ## P1

1. **The retention chart can hide valid values and overweight seat layouts.** Used-price estimates can exceed original MSRP, so a fixed 0–100% axis can clip a valid result. The row-level median also gives extra weight to trims with more seat-layout records. Define the observation unit explicitly, show the eligible sample size, and allow the axis to extend above 100%. Test both cases. [Retention chart and calculation](/Users/dan/Coding-Projects/ev-suv-comparison/docs/plans/insights-stories-v2.md:66)

2. **The shared filter leaves the new build-time failure cases uncovered.** The plan says every builder uses one cohort, then exempts Choice and Third Row. Existing price and value code assumes eligible rows exist, including an unseeded `reduce()` and direct indexing into `bestValueTrims()`. Define which stories use the shared filter and what each renders when it has zero eligible rows or no matched new/used pair. Add fixture tests for those cases. The output test should verify that the title agrees with the rendered stories when a story has insufficient data. [Filter contract](/Users/dan/Coding-Projects/ev-suv-comparison/docs/plans/insights-stories-v2.md:28) · [Existing empty-data assumptions](/Users/dan/Coding-Projects/ev-suv-comparison/lib/data-stories.ts:110) · [Test plan](/Users/dan/Coding-Projects/ev-suv-comparison/docs/plans/insights-stories-v2.md:100)

3. **The rollback covers the stories but omits the separately merged data PR.** The MSRP backfill changes existing trim displays before Market Insights ships. Historical MSRP already has a formatter, while the destination field displays a bare dollar amount. Verify both in the data PR and document how to correct or revert that PR independently under `data-contract`.
